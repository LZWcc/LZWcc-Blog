这是我和 ChatGPT 那次长对话的第三、四轮，前两轮在[上篇](/blog/chatgpt-frontend-talk-1/)。整理方式和上篇一样：我的话做了精简，ChatGPT 的回答放在引用块里，删减的地方用省略号标出。

## 关注度和归属感

上一轮聊到审美以后，我提了两件一直在想的事。

一件是关注度。我在推特上看到不少独立开发者反复发 AI Slop 式的内容：标题夸张，信息很少，有的只是很简单的指南，却能拿到不少 Star 和关注。我自己做的新标签页扩展 [Niwa](https://lab.lzwcc.xyz/project/niwa) 每天都在用，用着很顺手，发到社交媒体上却没什么人看。我不想用营销号那种方式起号，但还是忍不住比较。

另一件是归属感。现在 AI 生成的界面确实好看，Claude 的字体、配色、间距我就很喜欢。我能让它一口气搭出一个漂亮的网站，可总觉得还缺点什么，又说不清缺什么、该让它改哪里。而且靠 one-shot 提示词做出来的东西，效果再好，我也总觉得不是自己的。

## 获取关注是另一套能力

GPT 先把这两个问题分开。关于第一个：

> 软件开发能力与获取关注的能力，实际上是两套不同的能力。

它举了两个人：A 花三个月开发一个设计精美、性能良好的浏览器扩展，但不擅长表达和推广；B 花三天用 AI 做一个很普通的小工具，但已经有两万名关注者，也善于用简短的内容解释产品价值。B 很可能比 A 拿到更多 Star、浏览量甚至用户。

> 这并不说明 B 的产品质量更好，只能说明他拥有更有效的传播渠道。
>
> 但反过来也一样：A 的产品开发得更精致，并不自动意味着它对别人更有价值。

然后它问了一个我确实没想过的问题：

> 你可能低估了一个问题：别人为什么要使用 Niwa？
>
> 你现在是从开发者的角度评价 Niwa。
>
> 你知道它经过了哪些迭代，为什么选择特定布局，怎样设计日历组件，以及自己每天用起来有多顺手。
>
> 但一个陌生用户并不知道这些。
>
> 在他看来，这可能只是又一个浏览器新标签页扩展。
>
> ……所以问题不一定是 Niwa 不够好，而是你还没有找到一个让陌生人愿意尝试它的具体理由。

它把 GitHub Star、实际使用和产品质量分成三件事：Star 说明有多少人愿意关注或收藏，实际使用说明有多少人装了并且一直在用，产品质量说明它能多好地解决目标用户的问题。三者有关联，但不相等。一个教程仓库拿到 500 Star，不代表它的工程质量胜过只有 5 Star 的项目；但一个适合新手的操作指南，也可能确实解决了很多人的问题。

> 简单不等于没有价值，复杂也不等于更有价值。

> 不喜欢营销号式的内容，不等于不应该学习怎样表达自己的作品。

它建议我分享真实的设计过程，比如为什么选这种日历布局，为什么放弃某个交互，为什么删掉一个看起来很漂亮的动画，这些都不需要夸张包装。它也说：

> 当然，这不保证你会获得很多关注。
>
> 社交媒体的分发规则本来就不完全由内容质量决定。

## 作品怎样才算自己的

关于第二个问题，GPT 谈的是创作意义上的归属感。它设想了三种情况。第一种，我让 Claude 做一个漂亮的个人主页，它完成设计、排版、动效和代码，我觉得不错就直接部署。第二种，我先收集十几个喜欢的网站，明确想要什么样的排版、字体、配色和交互，再让 Claude 按这个方向实现。第三种，我不仅提供参考，还在开发过程中主动决定：

> 这里的导航太抢眼，应该降低视觉权重。
>
> 这里的动画虽然流畅，但会干扰阅读，应该取消。
>
> 这里的卡片间距应该与整个页面的排版节奏一致。
>
> 这里的布局虽然不够常规，但我希望保留这种独特性。

三种情况里 AI 都参与了开发，它认为第三种更容易产生归属感，“因为你不是简单地接受它提供的结果，而是在逐渐形成、表达和落实自己的判断”。但它接着说：

> 如果你所有的判断都只是“好看”或者“不好看”，那么你的审美能力可能并没有得到多少提升。
>
> 你只是不断地在 AI 生成的方案之间挑选。
>
> 这也是为什么你会感觉自己没有学到什么。

## 识别美、解释美、创造美

> 你现在缺少的可能不是更多设计参考，而是把审美转化为知识的方法。

它把审美积累分成三层：

1. **识别美**：能感觉到某个网站很好看、某种动画特别自然，某个页面比 AI 默认生成的更精致。
2. **解释美**：能分析它为什么好看，是字重、留白比例、对齐关系、克制的颜色，还是动画节奏和交互反馈的配合。
3. **创造美**：做一个全新的页面时，不依赖已有网站的完整布局，也能按自己的设计原则组织页面。

> 你现在很容易从第一层直接跳到第三层。
>
> 看到一个喜欢的效果，让 Claude 复刻，然后让它放进自己的网站。
>
> 这当然能产生作品。
>
> 但第二层被跳过了。
>
> 因此，下一次遇到一个新的设计问题，你依然很难用语言向 AI 描述自己究竟想要什么。

它说，如果同时喜欢两种逻辑完全不同的设计，一种重视排版、留白和信息层级，一种重视视觉氛围、材质和动态表现，却没有分析原因，就容易让 AI 把两种风格混在一起，做出一个精致却缺少统一感的页面。所以收藏参考时，至少问自己三个问题：

1. 我具体喜欢它的哪个部分，而不是喜欢整个页面？
2. 这个效果为什么适合它所在的产品？
3. 如果把这个效果移植到 Niwa 或 UI Motion Lab，会不会破坏原本的风格？

> 设计能力不只是知道应该添加什么，还包括知道应该舍弃什么。

我说过用 AI 开发学不到东西，这一点它部分同意：如果每次不满意都只是让 Claude 再改，原因从来没被说出来，那确实没积累多少可复用的知识。办法不是回去手写所有代码，而是在让 AI 改之前，先自己写下不满意的具体原因，哪怕一开始很模糊，比如“这个导航切换时，其他元素都在动，我觉得不自然”，再让 AI 分析可能是布局重排、动画曲线不协调，还是多个元素的过渡时间不一致。下次遇到类似的问题，也许就能直接判断原因。它也补了一句：“设计判断力与编程实现能力并不是互相替代的。”

它建议我短期内不要再新建项目，而是拿 Niwa 首页做一次由我主导的设计迭代：找三到五个真正喜欢的参考，让 AI 分析其中的设计原则而不是照着模仿，由我决定采用哪些，再让 AI 实现；保留修改前后的版本，记下哪些改动真正改善了体验，哪些最后被我否定。

## 两个标准

这一轮最后，它指出了我的一个矛盾：

> 你现在似乎有点在用两个标准评价自己的作品。
>
> 一方面，你认为 AI 已经能完成绝大部分技术开发，因此不再特别看重独立编写代码的能力。
>
> 另一方面，当 AI 生成了一个很优秀的界面，你又因为自己没有亲自设计它，而觉得作品不属于自己。
>
> 这两个想法并不矛盾，但说明了一件事：
>
> 你不只是在追求开发效率，你其实也在追求创作过程中的参与感和成就感。

> 实用工具可以追求效率。
>
> 个人作品可以允许自己花很多时间打磨一个小细节，甚至手动尝试几种不同的动画实现。
>
> 这种时间不一定能换来更多关注，也不一定具备直接的商业价值。
>
> 但是，它可能正是你希望通过开发获得的东西。

它又问了一个问题：看到一个很喜欢的网站时，最吸引我的通常是整体视觉设计（字体、排版、配色、留白），还是那些精致、自然的交互和动画？

## GitHub 主页

我没有直接回答，而是发了两张截图过去。投实习时，我一般先发简历图片，再发一张 GitHub 主页截图。我希望 HR 和面试官看到的不只是贡献热力图，还能看出我在持续做产品，对前端审美和 AI 开发有实践。但截图里最显眼的是 1,073 次 Contributions 和几个说明不了什么的置顶仓库。我想优化主页，又不想堆满闪烁的统计卡片，Claude 那种克制的字体、配色和留白很吸引我。

> 让 GitHub 主页成为你的开发者作品集，而不是一张堆满统计卡片的个人名片。

GPT 看了我的仓库，指出三件事：专门用于 Profile README 的 `LZWcc/LZWcc` 仓库还是空的；Niwa、token-stats 已经公开，Niwa 的 README 也有截图、功能介绍和安装入口，却没有放进置顶；简历里最重要的 IoT 和 MaintPilot 是私有仓库，如果没有在线演示、截图或技术介绍，招聘方没法从 GitHub 验证这两段经历。

> 所以你的问题不是没有东西可以展示，而是最值得展示的东西没有被放到最醒目的位置。

它建议借鉴 Claude 的设计原则，而不是照搬它的配色：克制的强调色、清楚的文字层级、充足的留白和不喧宾夺主的装饰。技术栈徽章、访问计数器、贪吃蛇动画、闪烁的 GIF 和堆叠的统计卡片都尽量不用，README 也不要太长，免得把下面的置顶仓库推得太远。

它还找到了我给 WhiteTowerAI 的 [ohmygame](https://github.com/WhiteTowerAI/ohmygame) 提的三个已合并的 PR：[#129](https://github.com/WhiteTowerAI/ohmygame/pull/129) 双击空白画布打开添加节点菜单，[#177](https://github.com/WhiteTowerAI/ohmygame/pull/177) 修复框选和面板闪烁，[#230](https://github.com/WhiteTowerAI/ohmygame/pull/230) Option/Alt 拖拽复制节点（过程写在[这篇](/blog/option-drag-duplicate/)）。

> 因为它们都与复杂前端交互直接相关，而且已经被真实开源项目接受并合并。
>
> 这实际上比告诉 HR“我今年提交了 1,073 次代码”更能说明你的开发经验。

置顶仓库它建议换成 Niwa、token-stats、博客和 ohmygame 这几个，不为了凑满六个硬加。简历上它建议把贡献次数换成具体的开源成果；我的简历写了熟悉 ChatGPT、Claude Code、Codex，它说从这句话看不出使用深度，[token-stats](/blog/token-stats/) 可以当补充证据，但“Token 使用量只能说明使用规模，不能直接证明 AI 开发能力”。在招聘平台上，它建议保留简历图片，把 GitHub 活跃度截图换成一张最能体现产品质量的项目截图，再附上主页链接。

### 让 AI 写推文，算不算 AI Slop

我还问了它：如果让 Claude Code 读仓库，替我写一条推广推文，是不是也成了 AI Slop？

> AI 撰写内容，不等于 AI Slop。
>
> 决定内容价值的，不是它由谁来组织语言，而是内容里有没有真实的信息。

GPT 举的反例是“我使用最先进的 AI 技术开发了一款革命性浏览器扩展，重新定义新标签页体验”。正例它举了 Niwa 的小组件拖拽，说一开始是即时换位，后来改成位置稳定后再重新排列。这是它自己设想的，它没读过 Niwa 的代码。Niwa 里真实发生过的是快捷方式：拖着一个快捷方式经过别的图标时，原来是两两互换位置；后来参照手机桌面，改成插到指针所在的格子、其余图标顺移一格，而且要等指针停稳才让位，划过的格子都不动。这样一个真实的取舍，交给 AI 整理成推文，它认为没有问题，“因为核心的观察和判断来自你的实际经历”。

## 我现在怎么想

上篇最后，GPT 问我：如果 AI 能把任何网站都做到技术上无可挑剔，我最想亲自参与哪一部分。我现在的回答是审美。不同的 AI 有不同的审美和语言风格，大部分人都觉得 Claude 的前端审美比较好，但如果只靠它的审美，每个人写两三句提示词，做出来的东西都千篇一律。要把它做成自己的作品，还是要经过多轮对话，一次次决定留什么、改什么。

一开始我担心 AI 这么强，自己还有什么价值。现在我觉得瓶颈在人：一是能不能把自己想要的东西说清楚，二是审美和取舍。前几天让 Claude Code 改博客首页，我说的是左上角那张青蓝色的卡片，它理解成了顶上的导航栏，改了两次都没改对。如果我一开始就说清楚是哪一张，以现在的模型能力，一次就能改好。

网上常说 AI 会先淘汰前端，再淘汰后端。我的感觉正好相反：模型能力越强，前端的审美就越比后端重要。后端的代码，模型可以自己写、自己验证，验证不通过就接着改，直到全部通过；一个页面好不好看，没法这样自动验证。不过我没有参与过很庞大的项目，这只是我现在的感觉。

至于 GPT 的最后一个问题，喜欢一个网站时，我觉得视觉、交互和动画都重要，不想在里面选一个。
